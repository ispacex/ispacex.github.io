# Конвейер сборки /ksh/sv/ — Śivastotrāvalī

Страницы раздела **не пишутся руками**: они собираются из одной страницы
источника — [узла 1005](https://www.sanskrit-trikashaivism.com/en/scriptures-trika-scriptures-shivastotraavalii/1005)
на sanskrit-trikashaivism.com.

Главное, что нужно знать об этом писании: **переводить в нём почти не с чего.**
Санскрит выложен целиком — 450 строф, деванагари и транслитерация, — а
английское изложение написано только на вступление и на первые шесть строф
первого гимна. Под остальными 444 строфами стоит одно слово: `Untranslated`.

Отсюда и устройство конвейера. Он такой же, как у
[Parātrīśikāvivaraṇa](../pv/README.md) — перевод лежит здесь, в `ru/*.json`, и
доливается по строфам, — но каждая страница обязана сказать о себе правду
сразу: перевода нет не потому, что до него не дошли руки здесь, а потому, что
его нет и у источника.

## Шаги

```sh
python3 fetch.py           # исходная страница -> src/sv1005.html
python3 convert.py         # разбор вёрстки    -> blocks/<номер гимна>.json
python3 render.py          # сборка страниц    -> ../../ksh/sv/chN/index.md
python3 toc.py             # оглавление        -> ../../ksh/sv/index.md
python3 check.py           # четыре тихие поломки, см. ниже
```

## Чем этот источник отличается от соседних

**Всё писание — одна страница.** Части здесь режутся не по файлам, а по
заголовкам «Chapter N» внутри одного разбора: у каждого гимна на странице свой
якорь `#ChapterN`, туда и ведёт ссылка «Эта часть у источника». Поэтому
`convert.py` тут свой, а не общий.

**Строфа и её транслитерация стоят в одном абзаце**: две строки деванагари, под
ними те же две строки IAST. В Parātrīśikāvivaraṇa они лежат двумя стенами, и
`pairing` в `common/page.py` складывает стены построчно. Здесь складывать
нечего, наоборот: абзац разводится надвое на разборе, чтобы тот же `pairing`
собрал его обратно уже построчно. Стен из-за этого выходит не одна на страницу,
а по одной на строфу, — поэтому `book.py` переопределяет `pairing` и оставляет
кнопки копирования одни на гимн: копируют здесь гимн целиком, а не строфу.

**Пометки `Untranslated` в блоки не идут.** Показывать в рамке `pv-en` одно и то
же слово двадцать шесть раз подряд — не честность, а шум. Абзац с пометкой
выбрасывается на разборе, а счёт непереведённому ведётся по строфам, у которых
перевода не оказалось: этим занят `head_note` в `book.py`.

**У строфы есть свой адрес.** Номер берётся из хвоста её транслитерации
(`||13.11||`, а не `॥१३.११॥` над ним) и становится якорем: `/ksh/sv/ch13/#v13.11`.
Строфу здесь зовут по номеру — «Шивастотравали 13.11» цитирует
[«Тантралока»](/ksh/ta/), — и до сих пор такая ссылка вела в пустоту.

## Что где

| Файл | Что делает |
|---|---|
| `parts.py` | двадцать гимнов: названия, число строф по вступлению источника |
| `book.py` | чем «Шивастотравали» отличается от прочих писаний: кнопки, якоря, оговорка о непереведённом |
| `fetch.py` | скачивает исходную страницу |
| `convert.py` | одна страница → двадцать наборов блоков; строфа разводится с транслитерацией |
| `render.py` | блоки + переводы → страницы Jekyll |
| `todo.py` | что ещё не переведено из того, что переводимо |
| `toc.py` | состав и состояние перевода в оглавление раздела |
| `add.py` | дописать переводы, не потеряв уже написанное |
| `check.py` | четыре проверки переноса |

Общее — в `tools/common/`: `parse.py` (вёрстка → блоки), `page.py` (блоки →
страница), `fetch.py` (загрузка), `check.py` (сверка текста).

`src/` и `blocks/` — промежуточные, в репозитории их нет: `fetch.py` и
`convert.py` восстанавливают их за минуту.

## Как переводить

```sh
python3 todo.py 1          # непереведённые блоки первого гимна
```

Перевод дописывается в `ru/<номер гимна>.json` по номеру блока:

```python
from add import add
add('1', {26: 'русский текст…'})
```

Санскритское слово в переводе остаётся в скобке, как правит его рука; над
русским словом его поставит `render.py` на сборке. Скобки при этом не исчезают,
а уходят в `<rp>`: `/search-index.json` собирает Jekyll, снимая с абзаца теги, и
строка обязана совпасть с прежней знак в знак. Это и проверяет `check.py`.

## Что проверяет check.py

1. **Подстрочник не изменил текста** — общая проверка, `common/check.py`.
2. **Строф столько, сколько объявил источник.** Во вступлении Габриэль
   перечисляет их число по гимнам; на странице они лежат отдельно от этого
   перечня, и разойтись эти два счёта могут молча. Сейчас сходятся: 450.
3. **У каждой строфы есть транслитерация и номер.** Не сложилась пара — вместо
   строфы выйдут две стены; пропал номер — сломается якорь `#v13.11`.
4. **Каждый перевод — по-русски.** Абзац без кириллицы в `ru/*.json` значит, что
   туда попал английский текст источника, а не перевод.

## Вступление

Вступление переводчика переведено один раз на `/ksh/sv/`, откуда оно и взято.
В блоки оно не идёт: двадцати страницам оно ни к чему, а двадцать раз лежать в
поисковом указателе тем более не должно. Так же сделано у
[«Тантрасары»](../ts/README.md).

## Поиск

Отдельно ничего делать не надо. Указатель `/search-index.json` собирает сам
Jekyll, обходя страницы `.md`.
